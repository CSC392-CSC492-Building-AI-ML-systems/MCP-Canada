# Local data setup (comparison feature)

This guide takes you from a fresh checkout to a working neighbourhood comparison page with the
official datasets: Census, CMHC, CPI, schools, libraries, TTC stops, OpenStreetMap groceries,
Toronto Police crime rates and City of Toronto Green Spaces. It assumes you have not worked on this
feature before.

Run every command from the **repository root** unless a step says otherwise. On Windows, use
`backend\.venv\Scripts\python` where this guide shows `backend/.venv/bin/python`.

## What Git gives you, and what it doesn't

| Item | In Git? | How you get it |
|---|---|---|
| Code, tests, `data/official-sources.json` (pinned URLs and SHA-256 of every raw file) | Yes | `git pull` |
| `backend/uv.lock`, `backend/requirements.txt`, `frontend/package-lock.json` | Yes | `git pull` |
| `data/raw/*` (23 raw snapshots, about 106 MB) | No, ignored | Fetched by the setup script (below) |
| `data/normalized/official.json` (about 90 MB) | No, ignored | Generated by the setup script |
| `backend/db.sqlite3` and any `*.sqlite3*` backups | No, ignored | Created or updated by the setup script; never commit |
| `backend/.venv/`, `frontend/node_modules/` | No, ignored | `uv sync`, `npm ci` |
| `frontend/.env.local` (Mapbox token) | No, ignored | Copy `frontend/.env.local.example` (see README) |

## 1. Prerequisites

- **Git**.
- **uv** ([install](https://docs.astral.sh/uv/getting-started/installation/)). It installs
  **Python 3.12** (`.python-version`) for you.
- **Node.js 24** (`.nvmrc`; 20.19+ or 22.13+ also work) and npm. With nvm: `nvm install`.
- About **1 GB of free disk** (raw files, the bundle, the database and a backup).
- Internet access, or a folder holding the raw snapshot files (see "Offline or shared folder").

## 2. Install dependencies

macOS / Linux (bash or zsh):

```sh
cd backend
uv sync --locked   # Python 3.12 + exact versions from uv.lock, incl. shapely 2.1.2 and numpy 2.5.4
cd ../frontend
npm ci             # exact versions from package-lock.json
cp .env.local.example .env.local   # add your Mapbox token; see the README
cd ..
```

Windows PowerShell (one command per line; Windows PowerShell 5.1 has no `&&`):

```powershell
cd backend
uv sync --locked
cd ..\frontend
npm ci
Copy-Item .env.local.example .env.local
cd ..
```

Without uv: create the environment with `python3.12 -m venv backend/.venv` (Windows:
`py -3.12 -m venv backend\.venv`), then run
`backend/.venv/bin/python -m pip install -r backend/requirements.txt` (Windows:
`backend\.venv\Scripts\python -m pip install -r backend\requirements.txt`). This pins the direct
dependencies, including shapely; only uv's lock file also pins indirect ones such as numpy.

## 3. Prepare the database (one command)

Stop the Django server first, so the database is not being read while it is updated.

```sh
backend/.venv/bin/python backend/scripts/setup_official_data.py        # macOS / Linux
```

```powershell
backend\.venv\Scripts\python backend\scripts\setup_official_data.py    # Windows PowerShell
```

Add `--dry-run` to run every check without changing your database. Add
`--from-dir <folder>` to take missing raw files from a folder (see "Where the raw files come
from"). The script works from any directory, because it finds the project from its own location.

What it does, stopping at the first problem:

1. Checks Python 3.12+ and that every installed backend package matches `requirements.txt`.
2. Checks all 23 raw files against their pinned SHA-256. It fetches missing ones in this order:
   `--from-dir` folder, then the project data release, then the official source. It keeps a file
   only if its bytes match the pin, and never overwrites a file you already have.
3. Builds `data/normalized/official.json` with `prepare_official_data.py`.
4. **Dry run on a temporary copy** of your database: migrate, encoding repair, a full
   all-or-nothing import, and a check that every bundle record is present.
5. Only then updates your real database (see below) and checks the final counts.

A run takes about 8 minutes, because the importer checks every record for conflicts, even when
nothing has changed. If any step fails, the real database is left exactly as it was. A fresh
database is only created once validation has passed, and the import into an existing one is
all-or-nothing.

### Fresh database vs existing database

The script says which case it found.

- **No database yet (fresh):** the validated copy from step 4 becomes `backend/db.sqlite3`.
  Nothing is replaced.
- **Existing database:** it makes a timestamped backup next to it (for example
  `db.sqlite3.backup-20261114T030000Z`; existing backups are never overwritten), runs
  migrations, and imports. The importer **adds** missing records, never deletes any, and stops
  if a stored record conflicts with the bundle. `--no-backup` skips the backup.
- **Already up to date:** it reports that and writes nothing. Running the script again is safe.

**Encoding repair prompt.** If your database was imported on Windows before the UTF-8 fix,
4,856 staged source rows hold mis-decoded text such as `MÃ©tis`. The script shows examples
and asks you to type `REPAIR`. Only those rows' `label`, `metadata` and `cells` are rewritten to
the exact source text, and only after the backup. If you answer anything else, or run it without
a terminal, nothing is changed. A fresh or already-repaired database never asks.

To use a different database file, set `DJANGO_DB_PATH` to an absolute path. The script and
Django both read it.

### Where the raw files come from

All files are pinned in `data/official-sources.json`. On 2026-11-14, twenty of them were still
served byte-for-byte by their official URLs, so the script downloads those directly. Three can't
be downloaded again with the same bytes:

| File | Why it can't be re-downloaded |
|---|---|
| `osm-groceries.json` | Live OpenStreetMap (Overpass) query; returns different bytes every time |
| `crime-rates.csv` | The recorded ArcGIS export URL now returns HTTP 400, and the portal's CSV download has different columns |
| `toronto-green-spaces.geojson` | The City refreshes this dataset monthly, in place |

> **Current status: the project data release is not published yet.** The pins point to the
> GitHub release `official-data-2026-11-14`, which a maintainer publishes once the licence review
> below is signed off. Until then, the script reports `Could not obtain the pinned snapshot` for
> these three files.

**Until the release exists:** ask the feature owner for the three files. They share them
through the team's shared drive, not by email or chat, so the bytes arrive intact. Put them in a
folder, then run the script with `--from-dir` pointing at it:

```sh
backend/.venv/bin/python backend/scripts/setup_official_data.py --from-dir ~/Downloads/official-data
```

```powershell
backend\.venv\Scripts\python backend\scripts\setup_official_data.py --from-dir $HOME\Downloads\official-data
```

Files from a folder are accepted only if their checksum matches the pin, so a wrong or edited copy
is rejected. The other 20 files still download automatically. `--offline` never downloads
anything. Once the release is published, the folder is no longer needed.

## 4. Run the application

Use two terminals, both starting at the repository root.

```sh
# terminal 1 (macOS / Linux)
cd backend
uv run python manage.py runserver 127.0.0.1:8000
# terminal 2
cd frontend
npm run dev
```

```powershell
# terminal 1 (Windows PowerShell)
cd backend
uv run python manage.py runserver 127.0.0.1:8000
# terminal 2
cd frontend
npm run dev
```

On macOS, Linux or Git Bash, `./scripts/start-all.sh` starts both. It is a bash script, so it
does not run in PowerShell. Open http://localhost:3000/housing.

## 5. Check that it worked

1. The setup script ends with `Success:` and a table where every line reads
   `N of N bundle records`.
2. `backend/.venv/bin/python backend/manage.py data_inventory` (Windows:
   `backend\.venv\Scripts\python backend\manage.py data_inventory`) lists the sources, including
   `crime-rates-csv-21f0b84fa7`, `osm-groceries-json-189a307dfc` and
   `toronto-green-spaces-geojson-375b4de6cb`.
3. API checks with Django running:
   - http://127.0.0.1:8000/api/places/?category=grocery returns 2,128 places, each with `kind`.
   - http://127.0.0.1:8000/api/observations/batch/?geography_set_id=toronto-158&indicator_id=green-space-share&source_id=toronto-green-spaces-geojson-375b4de6cb
     returns 158 rows.
4. In the app, open **Compare** with two to five **Current 158** neighbourhoods and the year
   **2021**. You should see:
   - Schools, supermarkets & grocers, transit stops and parks within 1 km, each with "Denser
     than about N% of the 158 neighbourhoods".
   - "X% of the area is green space".
   - Safety (reported major crime per 100,000 residents).
   - Lifestyle match, if your profile has lifestyle priorities. Choose "Parks & green space" to
     see it scored.

   With 2001–2011, or Historical 140 areas that changed in 2021, Safety shows why it is
   unavailable instead of a number. Place lists and green space are labelled as current
   snapshots, not historical values.

## Common problems

| Message | Fix |
|---|---|
| `Backend dependencies do not match the pins` | Run `uv sync --locked` inside `backend`, then rerun with `backend/.venv` Python |
| Rows show counts but no "Denser than…" line, or no parks | The database predates these indicators: rerun the setup script, which adds them |
| `Python 3.12+ is required` | You ran the system Python; use `backend/.venv/.../python` |
| `exist but differ from the pinned snapshot` | Move that file out of `data/raw` (keep it if it is a newer snapshot to review) and rerun |
| `Could not obtain the pinned snapshot of …` | Check your internet connection and the release link above, or use `--from-dir` |
| `needs confirmation, and no interactive terminal` | Rerun in a normal terminal and type `REPAIR` |
| `Conflicting … record` from the importer | Stored data differs from the bundle. Do not edit the database: report it with the full message |
| `database is locked` | Stop `runserver` and any other tool using the database, then rerun |
| `UnicodeDecodeError: 'charmap' codec` | An old importer version; pull this branch (bundles are read as UTF-8) |
| `Turbopack is not supported … native bindings` or `not a valid Win32 application` | `node_modules` holds a broken native compiler: run `npm ci` inside `frontend`. Meanwhile `npx next dev --webpack` works |
| Port 8000 or 3000 in use | Stop the other server, or (bash) `BACKEND_PORT=8001 FRONTEND_PORT=3001 ./scripts/start-all.sh` |

### Licence review (checked 2026-11-14)

All three snapshots may be redistributed with attribution. The terms are also recorded in
`data/official-sources.json` (`licence`, `attribution`, `licence_conditions`). This is a
reading of the published terms, not legal advice; a maintainer should confirm it before
publishing.

|---|---|---|---|
| `osm-groceries.json` | [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/) | "© OpenStreetMap contributors", linking to https://www.openstreetmap.org/copyright | **Share-alike:** the file, and any publicly used database derived from it (our bundle or database rows), must stay under ODbL. Displayed results are produced works and need attribution |
| `crime-rates.csv` | [Open Government Licence – Ontario](https://www.ontario.ca/page/open-government-licence-ontario), as published by the Toronto Police Service (terms on its ArcGIS item) | "Contains information licensed under the Open Government Licence – Ontario." plus Toronto Police Service as source | No share-alike. | `toronto-green-spaces.geojson` | [Open Government Licence – Toronto](https://www.toronto.ca/city-government/data-research-maps/open-data/open-data-licence/) | "Contains information licensed under the Open Government Licence – Toronto." | No share-alike. Excludes personal information and third-party rights |

Points to confirm by hand:
- The tps.ca licence page blocks automated access. Its terms were read from the publisher's
  ArcGIS item metadata.
- The City's catalogue record for Green Spaces has no licence fields. The licence comes from the
  dataset page's link.

The compare page shows these attributions in "Sources & method". The `licence` stored in the
database for these two releases still says "not specified"; correct it with the next snapshot,
because changing it now would make existing databases fail import with a conflict.

### Publishing the release

Publish only after the licence review is signed off. Do this once from a computer that has the
verified files (all three must match the pins in `data/official-sources.json`):

1. Check them: `sha256sum data/raw/osm-groceries.json data/raw/crime-rates.csv data/raw/toronto-green-spaces.geojson`
   (Windows: `Get-FileHash -Algorithm SHA256 <file>`).
2. On GitHub, go to **Releases → Draft a new release**. Create the tag
   `official-data-2026-11-14` on the default branch, and give it a title like
   "Official data snapshots 2026-11-14".
3. Attach the three files with their exact names. In the description, list each file's SHA-256,
   licence and attribution from the table above. Say that the OSM file is © OpenStreetMap
   contributors, available under the ODbL 1.0, and link both the licence and
   openstreetmap.org/copyright.
4. Publish. With the GitHub CLI, the equivalent is
   `gh release create official-data-2026-11-14 data/raw/osm-groceries.json data/raw/crime-rates.csv data/raw/toronto-green-spaces.geojson --title "Official data snapshots 2026-11-14" --notes-file <notes>`.
5. Test it: move one of the files aside, run the setup script with `--dry-run`, and check that it
   reports `from release mirror`.

Never replace an asset in place. A new snapshot gets new pins in `data/official-sources.json` and a
new release tag.
